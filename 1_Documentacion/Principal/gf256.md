# gf256.py (Algebra de GF(2⁸))

El archivo `gf256.py` construye la S-box de AES desde cero con matematicas, para tener una referencia confiable (NL = 112, δ = 4) contra la cual calibrar el evaluador.

### POLY = 0x11B

Es el polinomio irreducible **x⁸+x⁴+x³+x+1** escrito en binario (1 0001 1011). En GF(2⁸), cuando una multiplicacion "se pasa" de 8 bits, se reduce modulo este polinomio.

### gf_mul(a, b): multiplicacion en GF(2⁸)

Es el algoritmo "suma y desplaza" (como multiplicar a mano en binario, pero la suma es XOR):

- `r = 0`: acumulador del resultado
- `while b`: recorre los bits de `b` de derecha a izquierda
- `if b & 1: r ^= a`: si el bit actual de `b` es 1, suna (XOR) `a` al resultado
- `a <<= 1`: duplica `a` (multiplicar por x).
- `if a & 0x100: a ^= POLY`: si `a` se salio de 8 bits, lo reduce con el polinomio. Asi siempre queda en 0..255
- `b >>= 1`: pasa al siguiente bit

**Ejemplo del FIPS-197 que se utiliza en la pruebas: {57}·{83} = {c1}.**

**`gf_inv(a)`: inverso multiplicativo -** Busca por fuerza bruta el `b` tal que `ab = 1`. Para `a = 0` devuelve 0 (convencion de AES, porque el 0 no tiene inverso). Es lento (hasta 255 multiplicaciones), pero solo se usa una vez para construir la S-box de AES, asi que no importa.

**`_rotl8(x, n)`: rotacion circular de 8 bits a la izquierda -** Desplaza `x` a la izquierda `n` posiciones y los bits que se salen reentran por la derecha. El `& 0xFF` recorta a 8 bits.

**`affine(x)`: transformacion afin de AES -** Es `x ⊕ rotl(x,1) ⊕ rotl(x,2) ⊕ rotl(x,3) ⊕ rotl(x,4) ⊕ 0x63`. Es la forma compacta de la multiplicacion matricial que define el estandar. Su papel es romper la estructura algebraica del inverso puro. 

**`aes_sbox()` -** Para cada byte `x` de 0 a 255: `affine(gf_inv(x))`. Eso es literalmente la definicion de la s-box de AES (inverso + afin). Devuelve una lista de 256 enteros, o sea, una permutacion: justo la representacion π que se usa en todo el proyecto.
